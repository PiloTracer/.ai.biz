### Changed

The `.work.biz/`-only write/stage/commit scope (path-scoped `git add -A -- .work.biz` + `git commit -- .work.biz`) is unchanged, and the CONTENT_STATUS pipeline brief on start is kept
- **Session routing surfaces** — `skills/README.md` (skill row + `commit`/`push` vocabulary + new `add` verb), `.cursorrules` + `templates/cursorrules.template` biz-session rows, `START_HERE.md` §6 (close variants + mid-session checkpoints), `.quick/session-lifecycle.md` (full command set), `SKILL_DEPENDENCIES.md` system-skills paragraph, `biz-director` session-management intents ("commit my progress", "checkpoint without closing"), and `PROCESS_ROUTER.md` (standalone commit row) all describe the new surface
- **`biz-session` commit scope is repo-role aware** — in the Business OS source repo (framework at git root, detected via `skills/biz-session/skill.md` at the root) `commit`/`push` stage and commit **all** modified/added/new files repo-wide (`git add -A`); in a target project the scope stays `.work.biz/` only. File writes remain `.work.biz/`-only in both roles. Owner directive: source-repo session commits must not leave framework changes behind

### Added
- **Content Status Protocol (CONVENTIONS § Content Status Protocol)** — the binding read/write contract for `.work.biz/reference/CONTENT_STATUS.md`. Publish tracking was broken in target projects by construction: the tracker existed and `biz-session` loaded it, but only one of four content paths ever wrote to it (`biz-content challenge`'s posting ritual). `biz-content publish`, `biz-youtube publish`, `biz-social write`, and `biz-writing` neither read it before drafting nor recorded into it after publishing, so the file starved, later sessions could not tell what was live, and agents re-drafted already-published topics. The protocol defines five lifecycle states (`draft`, `ready`, `published`, `blocked`, `hold`), a read rule (every content skill reads before drafting; never re-draft a published piece; prefer advancing `ready`/`draft` pieces), a write rule (drafts registered on delivery, publishes recorded by whichever flow shipped them), and a self-heal rule (create the tracker from its template at record time when missing, instead of skipping the record)
- **`@biz-social log` (I7)** — explicit recording path for publishes that happened outside any skill, which is most publishes: operator posts from a phone, or a draft goes live between sessions. Promotes the existing Items row rather than duplicating it, refreshes By platform and Summary, runs the tracker's "What to do after a publish" checklist, and flags channel-plan drift without blocking the record. Ungated, 1-2 min per piece. Routed from `biz-director` ("I published the post", "mark this piece published"), listed in `skills/README.md` verb table, `START_HERE.md`, `PROCESS_ROUTER.md`, `.cursorrules`, and `templates/cursorrules.template`
- **Tracker wiring in all four content skills** — `biz-content publish` gains step 0 (load tracker, prefer ready/draft pieces) and step 7 (record the publish, mandatory); `biz-writing` gains the tracker in its I0 context load and a Step 7 registering delivered pieces (`ready`, or `draft` when an owner pass is pending) plus a completion-gate item; `biz-social` gains the tracker in I0, a Step 5 registration, and a time-budget row; `biz-youtube publish` gains step 0 and step 7 (record into both `CONTENT_STATUS.md` and `youtube-tracker.md`), and its `status` mode reads the index first. `biz-content status` and `biz-youtube status` now reconcile: any post the operator names that is missing from the tracker gets recorded
- **`framework-verify.sh` content-status wiring check** — fails when any of the four content skills stops referencing `CONTENT_STATUS.md`, when CONVENTIONS loses the protocol section, or when the verb table loses `log`. This failure mode is silent by nature (the tracker simply stays empty in target projects), so it gets the same treatment as the `WORK_FILES` manifest drift: a machine check where prose review already proved insufficient
- **Real `blast-radius-check.sh --self-test`** — exercises a temp git repo through four scenarios (clean tree, one staged area amid three changed areas, three staged areas, `--warn-only` override) instead of printing PASS unconditionally
- **`@biz-review monthly` (I1b) — assumption re-validation.** Certification is one-shot and the weekly drift check compares dates, not evidence, so nothing kept the strategy true after the cert date. Monthly re-grades every `assumption-ledger.md` row (Confirmed / Inferred / Unknown / Dead) against fresh pipeline, tracker, and call evidence, records a `Re-validated` date, and classifies dead assumptions as load-bearing or peripheral. A dead load-bearing assumption routes to `@biz-strategy amend` immediately; peripheral deaths queue in NEXT. Re-validation never rewrites positioning itself
- **`@biz-strategy career` (I2d) + `reference/OPERATOR_PROFILE.md`** — every skill assumed an operator profile and nothing recorded one. Career mode probes skills, proof points (numbers and dates required), constraints, risk tolerance, career stage, and direction; fills the new template; and produces a Hold / Sharpen / Transition career-direction read with graded claims, cross-checking any certified strategy against the profile. The profile lives in `reference/` by design: it is input to positioning, not a positioning decision, so it moves no gate and never trips the drift check. Scaffolded by bootstrap + deploy manifests; read by `biz-writing` and `biz-social` (I0), `biz-content` (I0c), `biz-youtube` (operator proof), and `biz-pricing` (I0b: runway and capacity bound the price floor); `greenfield` offers it before Element 1
- **`reference/PROJECTS.md` proof-point bank template** — the DIRECTORY_MAP entry was dangling (no template), and four sales skills referenced the file as create-on-first-use with nothing to create it from. Now scaffolded by bootstrap + all manifests, with per-project blocks (numbers, stack, what made it hard), a binding disclosure-status rule (private clients stay anonymized), and a proof-point index. Self-heal wording updated in `biz-brand`, `biz-objections`, `biz-discovery`; wired into the four content skills' proof loads
- **Content-strategy pillar loop** — `CONTENT_STATUS.md` gains a **By pillar** section and a Pillar column on Items; a pillar is one of the 3-5 strategic messages traceable to one-pager/offer. Drafting skills assign the pillar at registration (`biz-writing` Step 7, `biz-social` Step 5 and `log` mode, `biz-content` step 7, `biz-youtube` step 7), plan modes map every topic to a pillar and report pillars the calendar leaves silent, and `@biz-review quarterly` gains a **Content-strategy alignment** section: aggregate the quarter's conversations per pillar (Converting / Reaching only / Silent / Untracked) and feed persistent results back through `@biz-strategy amend`. This is how content performance flows back into strategy instead of dying in the tracker
- **Voice loop enforcement (CONVENTIONS § Voice loop)** — the retro existed but nothing forced entries, so voice convergence was measured on a partial sample. Every publish flow now records its `VOICE_RETRO.md` entry in the same session (done / waived, edit count, edit classes), the tracker's post-publish checklist carries it, `biz-review weekly` checks retro coverage against publishes, and skeleton `VOICE_PROFILE.md` files (placeholders unfilled) are treated as absent with a plain warning in all four content skills and `@biz-bootstrap status`
- **Appeal standard (Content Standard § Appeal standard)** — six binding bars above the anti-AI floor: defensible position, scene-or-number opening, named stakes with the feeling at the moment, specificity quota (one proper noun, number, or named artifact per 150 words), the so-what bar, and emotional concreteness. Wired into `biz-writing` (Position step-1 question, position/scene self-critique tests, checklist), `biz-social` (universal format + checklist), and `biz-content` (hook selection rule + step 5). Truth clause included: sharpness never justifies invented detail
- **Content pipeline brief at `@biz-session start`** — when the tracker loads, the session opens with a 3-5 line brief: ready pieces awaiting a post, drafts awaiting an owner pass, last publish date, unclassified published pieces, and one suggested action. A tracker that is read but never acted on is indistinguishable from no tracker
- **Evidence discipline rule (CONVENTIONS)** — statistics that state how the world *is* require an inline citation or an explicit directional marker in the same line; advice numbers (buffers, format specs, price math) are exempt by nature. Applies to framework prose as much as produced content
- **`framework-verify.sh` bootstrap↔WORK_FILES manifest sync check** — fails when `templates/bootstrap.sh` destinations and `biz-deploy-basic.sh` `WORK_FILES` diverge. `WORK_FILES` is the manifest that fails silently (`--update` only offers files listed there), so divergence gets a machine check rather than another prose-review hope

## [v0.6.0] - 2026-08-06

### Added
- **`@biz-strategy reconcile` (I2c) — a lightweight path for consistency repairs.** `amend` was the only way to touch a canonical strategy file, and it always demotes `strategy-ready` and cascades to three downstream gates. So correcting a file that contradicts *its own certification* cost four gates and a re-certification, which pressured operators to leave inconsistencies unrecorded — the opposite of what the gate system is for. Reconcile applies only when a decision the certified record already asserts was never transcribed into a canonical file. Deliberately hard to qualify for: four eligibility conditions must be proven with a direct quote from the certified source before anything is edited, and failing any one of them routes back to `amend`. Moves no gate, requires no re-certification, and logs to `strategy/changelog.md` marked **(correction)**
- **Graded-claims rule in the Content Standard** — commentary on external events must visibly separate **Verified** (sourced fact), **Inference** (own judgment, labeled), and **would check / would prove me wrong**, in the text rather than a footnote. Commentary inherits other people's facts, and grading is what keeps their errors from becoming the author's. This is the content-side counterpart of the assumption ledger the agent rules already require for planning work. Includes the ~70/30 experience-to-commentary ratio, whose failure mode is reach without buyers
- **`.work.biz/reference/VOICE_RETRO.md` — voice convergence measurement.** `templates/work/reference/VOICE_RETRO.md.template`, scaffolded by `bootstrap.sh` and `@biz-bootstrap init`. A voice profile is a hypothesis, and the only evidence it is right is that the owner stops fixing the same things. One entry per published asset records what the draft said and what the owner changed; owner edits per piece should fall over time. When an edit class appears three times, `VOICE_PROFILE.md` gets amended rather than the owner making the same correction forever. Tracks edit *classes* rather than instances, since only classes are actionable
- **`biz-director` routes for the new platforms and for two intents it never had** — Substack and Threads were added to `biz-social` without the router's trigger vocabulary knowing them, so "write a Substack piece" matched no intent phrase. Also adds explicit rows for **content strategy** (which requires reading `channel-plan.md` first and serving a certified plan rather than producing a fresh platform matrix) and **content scripts** (which must ask which platform, since script structure differs sharply). Resolves two naming collisions: "newsletter" as a format routes to `biz-writing` while Substack as a platform routes to `biz-social`, and a "thread" of tweets on X is not Meta's Threads, which have opposite register rules
- **`.work.biz/reference/VOICE_PROFILE.md` — canonical, cross-platform voice definition.** `templates/work/reference/VOICE_PROFILE.md.template`, scaffolded by `bootstrap.sh` and `@biz-bootstrap init`. Nothing previously defined *how the owner sounds*: the Content Standard supplies universal negative constraints plus generic human-voice advice, both identical for every adopter, so voice was re-derived from scratch every session and output read as generically human. Modeled on a proven consumer-project artifact: voice defined by **reference sample** rather than description (descriptions drift, samples don't), an explicit **texture** section whose rules may not be "corrected" away, a **precedence table** making the anti-AI-artifact rules an unoverridable floor while the generic human-voice rules become overridable defaults, an owner-pass declaration, and drafting rules barring invented facts and manufactured typos

A voice file scoped to one directory only applies while working in that directory, which is how single-platform voice discipline happens by accident

### Changed (content and channel discipline)
- **`repurpose` no longer produces a block per platform unconditionally** — it now produces blocks only for platforms `strategy/channel-plan.md` sanctions. A nine-platform dump looks productive while creating publishing obligations a solo operator cannot meet
- **`biz-social strategy` mode gained binding rules** — rate platform fit on *capacity* rather than audience match alone (a platform the buyer uses but the operator cannot sustain is a POOR fit), respect an existing channel plan rather than relitigating it, name the recorded reason when a platform sits on the plan's exclusion list, distinguish authority channels from pipeline channels, and check prior content performance before recommending more surfaces
- **Channel-plan check added to `biz-social` and `biz-youtube`** — producing for a platform absent from the channel plan, or on its "explicitly not channels" list, is surfaced before delivery, so tooling cannot quietly expand the channel mix past what the strategy sanctions. `@biz-strategy amend` is named as the way to change the plan on the record
- **Documented the repurposing asymmetry** — compression down works, expansion up produces padding. A LinkedIn post expanded into a Substack piece reads as inflated, because the compression that made it good on LinkedIn removed the narrative the subscriber came for
- **`CONTENT_STATUS.md` gained a by-platform index** — with a role column that must match the channel plan, a tracker-file pointer, and a conversations column. Per-platform metrics stay in the tracker files, since a single shared schema forces every platform to be measured by impressions

- **`templates/bootstrap.sh` silently scaffolded into the wrong repo** — it ignored positional arguments, and its `REPO_ROOT` fallback resolves to the Business OS repo itself when that is a git repo. - **Gate ledger reading was too strict for real ledgers** — the parser required `**Status:**` to equal `PASS` exactly and matched gate headings literally. Mentions in prose no longer trip it
